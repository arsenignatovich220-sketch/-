# <h3 align="center"> Тема: “Команди Linux для управління процесами”
### Мета роботи: 
- Отримання практичних навиків роботи з командною оболонкою Bash.
- Знайомство з базовими командами для управління процесами.
### Словник термінів:
- Process — процес (програма, яка виконується в системі).
- PID (Process ID) — ідентифікатор процесу (унікальний номер).
- PPID (Parent Process ID) — ідентифікатор батьківського процесу (який запустив поточний).
- Userid / UID — ідентифікатор користувача, який запустив процес.
- TTY (Teletypewriter) — термінал, з якого запущено процес.
- CPU time — процесорний час, який використовує програма.
- Child process — дочірній процес.
- Parent process — батьківський процес.
- Zombie — «зомбі» (процес, який завершився, але його батьківський процес ще не зчитав статус завершення).
- Robustness — надійність, гнучкість, потужність (утиліти).
- Unix-style parameters — параметри в стилі Unix (пишуться з одним дефісом, наприклад, -e).
- BSD-style parameters — параметри в стилі BSD (пишуться без дефіса, наприклад, aux).
- GNU long parameters — довгі параметри GNU (пишуться з двома дефісами).
- Hierarchical format — ієрархічний формат (відображення дерева процесів «батько-нащадок»).
- Full format listing — повний формат виведення (розширене відображення колонок інформації).
- Long listing — довгий (детальний) формат списку.
- Sleeping — стан очікування / сну (процес чекає на подію або ресурс).
- Runnable / Running — готовий до виконання / виконується в даний момент.
- Stopped — зупинений або поставлений на паузу.
- Priority (PRI) — пріоритет процесу (чим більше число, тим нижчий пріоритет).
- Nice value (NI) — показник «любезності» (рівень поступливості процесу при розподілі ресурсів процесора).
- Load average — середнє завантаження системи (за останні 1, 5 та 15 хвилин).
- Polling interval — інтервал опитування (частота оновлення даних у top).
- Interprocess communication — міжпроцесна взаємодія.
- Process signal — сигнал процесу (зумовлене повідомлення для керування програмою).
- To hang up (HUP) — обірвати зв'язок / закрити термінал (сигнал 1).
- Interrupt (INT) — перервати роботу з клавіатури (наприклад, через Ctrl+C, сигнал 2).
- Kill (unconditionally terminate) — безумовно примусово завершити (сигнал 9, який не можна ігнорувати).
- Terminate (TERM) — завершити, якщо це можливо (м'яке прохання закритися, сигнал 15 за замовчуванням).
- Resume execution (CONT) — відновити виконання (після паузи).
- Runaway process — непідконтрольний процес (що «зациклився» і надмірно споживає ресурси).
- Wildcard characters — символи підстановки / маски (наприклад, знак * для вибору кількох процесів за назвою).
### Завдання для попередньої підготовки:
##### Команди для моніторингу стану процесів та перегляд їхніх параметрів
Для моніторингу процесів використовуються команди ps (показує зріз інформації на конкретний момент часу) та top (показує стан процесів у реальному часі). Щоб переглянути всі можливі параметри, ключі та детальну документацію для цих утиліт, у Linux використовують вбудовану систему керівництва — команду man (наприклад, man ps або man top).
##### Чи може команда ps відслідковувати стан процесів у реальному часі?
Ні, не може. Команда ps робить лише одноразовий статичний знімок (snapshot) стану процесів у конкретний момент часу. Для динамічного відстеження змін та трендів у реальному часі вона не підходить — для цього використовують команду top.
##### Сортування процесів у команді top та перемикання між ними
За замовчуванням top сортує процеси за рівнем використання процесора (%CPU). Також процеси можна сортувати за іншими параметрами, наприклад: за використанням оперативної пам'яті (%MEM), ідентифікатором (PID), часом роботи (TIME+) чи пріоритетом. Щоб змінити критерій сортування, потрібно під час роботи програми натиснути інтерактивну клавішу f (Field Management), яка відкриває меню вибору та налаштування полів для сортування екранного виводу.
##### Команди для завершення роботи процесів
Для зупинки та завершення процесів за допомогою сигналів використовуються дві основні команди:
- kill — завершує процес за його унікальним ідентифікатором (PID). За замовчуванням надсилає м'який сигнал TERM (15), але дозволяє вказати й інші (наприклад, примусовий KILL (9) через прапорець -s).
- killall — завершує процеси за їхньою текстовою назвою (наприклад, killall httpd), а також підтримує використання символів підстановки (wildcards, наприклад *), що дозволяє зупинити групу однойменних процесів одночасно.
### Хід роботи:
#### 2.Bідповіді на питання:
##### 1)Директорія /proc: розташування, призначення та вміст:
- Де знаходиться: Директорія /proc розташована в кореневому розділі файлової системи Linux.
- Для чого призначена: Це віртуальна файлова система (pseudo-filesystem), яка не займає місця на жорсткому диску. Вона створюється ядром Linux у оперативній пам'яті під час завантаження системи і слугує вікном у роботу ядра та процесів.
- Як вивести вміст: Звичайною командою виведення списку файлів: ls -l /proc.
- Характеристика вмісту:
  - Цифрові папки (наприклад, /proc/1, /proc/3081): Кожна папка з числовою назвою відповідає активному процесу в системі, а саме число — це його PID. Всередині містяться файли з параметрами запуску, картами пам'яті та статусом конкретного процесу.
	- Системні файли: Файли без цифр містять загальну інформацію про апаратну частину та ядро. Наприклад:
	- /proc/cpuinfo — детальні дані про процесор.
	- /proc/meminfo — стан оперативної пам'яті (swap, вільна, зайнята пам'ять).
	- /proc/version — версія ядра Linux.
##### 2)Виведення інформації про поточні сеанси користувачів
Дізнатися, які користувачі зараз увійшли в систему та чим вони займаються, можна за допомогою таких команд:
- w — показує найповнішу інформацію: хто увійшов, з якого термінала/IP, час підключення, поточне завантаження системи (load average) та яку команду користувач виконує прямо зараз.
- who — виводить простий список активних користувачів, їхні термінали та час входу.
- users — виводить лише короткий список імен користувачів в один рядок.
##### 3)Дії у терміналі за допомогою гарячих клавіш
- Ctrl + C — перериває (вбиває) процес, який зараз виконується на передньому плані. Надсилає системний сигнал INT (Interrupt). Програма негайно зупиняє свою роботу.
- Ctrl + Z — призупиняє (ставить на паузу) процес на передньому плані та переводить його у фоновий режим. Надсилає сигнал TSTP. Програма застигає в пам'яті, звільняючи термінал для введення інших команд.
- Ctrl + D — сигнал кінця введення (EOF — End of File). Якщо натиснути в чистому рядку термінала, це завершить поточний сеанс оболонки (аналог команди exit). Якщо програма очікує введення тексту з клавіатури, це каже їй, що введення закінчено.
##### 4)Відмінність фонового процесу від звичайного
- Звичайний (інтерактивний) процес: Виконується на передньому плані (foreground). Він повністю займає термінал: поки програма не завершиться, ви не можете вводити нові команди.
  - Де використовується: Для роботи, яка потребує постійної взаємодії з користувачем (текстові редактори типу nano, утиліта top).
- Фоновий процес (background): Виконується непомітно для користувача, «за лаштунками». Він відпускає термінал одразу після запуску, дозволяючи вам продовжувати роботу.
  - Де використовується: Для тривалих завдань, які не потребують уваги (архівація великих папок, завантаження файлів з мережі, робота системних служб). Запускається додаванням символу & в кінці команди (наприклад: sleep 100 &).
##### 5)Команди jobs, bg, fg
- jobs — виводить список усіх фонових та призупинених завдань (jobs), які були запущені саме з поточного термінала. Кожному завданню присвоюється свій внутрішній номер у квадратних дужках (наприклад, [1]).
- bg (background) — відновлює роботу раніше призупиненого (через Ctrl + Z) процесу, але залишає його виконуватися у фоні. Використання: bg %1 (де 1 — номер завдання з команди jobs).
- fg (foreground) — повертає фоновий або призупинений процес назад на передній план. Термінал знову блокується цією програмою. Використання: fg %1.
##### 6)Перегляд фонових процесів та задач системи
- Якщо потрібно побачити завдання, запущені в рамках поточного термінала, використовується команда jobs.
- Якщо потрібно побачити абсолютно всі фонові процеси та системні демони (служби) в масштабах усієї системи, використовується команда ps -ef або ps aux.
##### 7)Призупинення, відновлення та перезапуск фонового процесу
- Як призупинити: Якщо процес працює на передньому плані, натисніть Ctrl + Z. Якщо він вже працює у фоні, надішліть йому сигнал зупинки через команду kill -s STOP <PID> (або вказавши номер завдання kill -17 %1).
- Як відновити:
  - Щоб процес продовжив роботу у фоні, введіть bg %Номер_завдання.
  - Щоб повернути його на передній план, введіть fg %Номер_завдання.
- Як перезапустити (якщо мається на увазі продовження після паузи): Надсилається сигнал продовження роботи CONT. Це можна зробити системною командою kill -s CONT <PID> або виконавши вищезгадану команду bg/fg. Процес продовжить виконання з тієї самої точки, на якій його зупинили.

##### 4) 5 прикладів використання команди ps з різними параметрами
###### 1. ps -e або ps -A
	- Що робить: Виводить абсолютно всі процеси, які зараз запущені в операційній системі, незалежно від того, якому користувачу чи терміналу вони належать.
###### 2. ps -u root
	- Що робить: Фільтрує процеси за користувачем. У цьому випадку виводить лише ті програми, які запущені від імені суперкористувача (root).
###### 3. ps -ef
	- Що робить: Виводить повний перелік процесів (-e) у розширеному повному форматі (-f). Додаються інформативні стовпчики: UID (власник), PPID (батьківський процес) та STIME (час старту).
###### 4. ps aux
	- Що робить: Популярний BSD-стиль виведення. Показує процеси всіх користувачів (a), з детальним відображенням власника (u) та процеси, які не прив'язані до поточного терміналу (x), включаючи системні служби. Тут також наочно видно відсоток використання пам'яті (%MEM) та процесора (%CPU).
###### 5. ps --forest (або ps -eH)
	- Що робить: Відображає дерево процесів. За допомогою графічних символів (гілок) наочно показує ієрархію: який саме процес породив (PPID) поточний дочірній процес.

### Контрольні запитання:
#### 1.Призначення директорії /proc та її інформація:
- Призначення: Директорія /proc — це віртуальна файлова система (pseudo-filesystem) або «процесна файлова система». Вона не існує на жорсткому диску, а генерується безпосередньо ядром Linux у оперативній пам'яті (RAM) під час завантаження системи. Вона слугує інтерфейсом для взаємодії між ядром та простором користувача.
- Що вона зберігає:
  - Інформацію про процеси: Для кожного запущеного процесу створюється папка, назвою якої є його PID (наприклад, /proc/1234). Усередині містяться файли з параметрами запуску (cmdline), картами пам'яті (maps), статусом обробки (status) тощо.
  - Стан апаратної частини та ядра: Файли поза цифровими папками відображають системну інформацію: /proc/cpuinfo (дані процесора), /proc/meminfo (використання оперативної пам'яті), /proc/uptime (час роботи системи) та параметри конфігурації ядра (у папці /proc/sys).
#### 2. Динамічне визначення найбільш «ненажерливого» процесу серед трьох:
Щоб динамічно (в реальному часі) моніторити лише три конкретні процеси, знаючи їхні PID (наприклад: 1024, 2048, 3072), використовуйте команду top із прапорцем -p:
bash
top -p 1024,2048,3072
- Як визначити лідера: За замовчуванням top сортує процеси за CPU. Щоб перемкнути сортування на використання пам'яті, натисніть клавішу M (велику літеру M, або Shift + M). Процес, який опиниться на самому верху списку, і є тим, що використовує найбільший обсяг пам'яті в поточний момент.
- Відсоток пам'яті: Скільки саме відсотків пам’яті споживає цей процес від загального обсягу системи, чітко показує стовпчик %MEM у його рядку.
#### 3.Ієрархія батьківських процесів в Linux
###### Отримати ієрархію процесів («дерево») можна за допомогою команд:
ps -ef --forest
######  або спеціальною утилітою:
pstree -p
##### Структура та характеристика ієрархії:
Структура будується за принципом «батько-нащадок» (Parent-Child) і завжди бере свій початок від головного процесу системи:
- systemd (PID 1) або init: Перший процес, який запускає ядро під час завантаження. Він є коренем усього дерева і «предком» усіх інших процесів у системі.
- Системні служби (демони): Від systemd відгалужуються фонові процеси (наприклад, sshd, cron, NetworkManager).
- Сеанс користувача: Коли користувач підключається, запускається менеджер дисплея або сервер SSH, який породжує процес командної оболонки (наприклад, bash).
- Кінцеві утиліти: Коли ви вводите команду всередині термінала, bash стає батьківським процесом (PPID), який народжує дочірній процес (наприклад, ps або top). Як тільки дочірній процес завершується, гілка зникає.
#### 4.Відмінність команди top від ps:
- ps (Process Status): Робить одноразовий статичний знімок стану процесів на поточну секунду. Вона вивела результат і відразу завершила роботу. Використовується, коли потрібно швидко зацитувати, відфільтрувати або передати список процесів в інший скрипт.
- top (Table of Processes): Працює в інтерактивному динамічному режимі. Вона залишається відкритою, постійно блокує термінал і оновлює інформацію на екрані кожні кілька секунд. Використовується для моніторингу системи "наживо".
#### 5.Додаткові можливості htop у порівнянні з top:
Утиліта htop є сучасною та набагато зручнішою альтернативою класичному top:
- Візуальні графіки: Показує кольорові та інтуїтивно зрозумілі шкали завантаження для кожного ядра процесора окремо, а також для RAM та Swap-пам'яті.
- Зручна навігація: Підтримує прокручування списку процесів як вертикально, так і горизонтально (можна побачити повні довгі назви команд) за допомогою стрілочок на клавіатурі або миші.
- Вбудоване дерево: Дозволяє перемикатися на деревоподібний вигляд процесів натисканням однієї клавіші (F5), без потреби запускати інші команди.
- Інтерактивне керування: Керування процесами (зміна пріоритету nice через F7/F8 або надсилання сигналів закриття kill через F9) здійснюється через зручне нижнє меню за допомогою функціональних клавіш, без необхідності вручну вводити PID процесу.
- Пошук та фільтрація: Можна миттєво знайти процес за назвою або відфільтрувати список.
#### 6.Компоненти мобільної ОС для моніторингу процесів:
##### В ОС Android:
- Running Services (Запущені служби): Головний інструмент моніторингу, розташований у Налаштуваннях для розробників. Він показує список активних додатків, фонових служб, обсяг споживаної ними оперативної пам'яті (RAM) та час їх безперервної роботи.
- Вкладка «Пам'ять» (Memory): Відображає середнє використання ОЗП системою за останні 3, 6, 12 або 24 години, а також дозволяє ранжувати додатки за їхньою «ненажерливістю».
- Віртуальна файлова система /proc: Як і в настільному Linux, в Android ядро операційної системи динамічно створює метадані про всі процеси у фоновому каталозі /proc, до якого мають доступ системні монітори
#### 7.Термінальне керування роботою процесів:
- В Android (Підтримується): Оскільки Android базується на ядрі Linux, він має повну низькорівневу підтримку командного рядка. За замовчуванням у графічному інтерфейсі термінала немає, але якщо встановити консольний емулятор, ви отримаєте доступ до вбудованої оболонки sh (або mksh) та утиліти toolbox/toybox. Ви можете виконувати стандартні команди:
  - top — для перегляду активності в реальному часі.
  - ps — для виведення зрізу процесів.
  - kill <PID> — для завершення завдання.
	- Важливо: Без Root-прав (прав суперкористувача) ви зможете переглядати та «вбивати» лише ті процеси, які належать вашому поточному користувачу (самому емулятору термінала або базовим прикладним програмам). Для керування системними процесами потрібен повний Root-доступ (команда su).
#### 8.Сторонні програмні засоби моніторингу та управління
##### Для Android:
- Termux: Найпотужніший емулятор термінала та середовище Linux для Android. Він має власний менеджер пакетів (pkg), що дозволяє встановити повноцінну утиліту htop з кольоровими графіками, а також pstree для моніторингу дерева процесів телефона безпосередньо з екрана мобільного.
-  3C Task Manager / System Status: Графічні диспетчери завдань (аналоги Диспетчера завдань Windows). Вони малюють графіки частоти ядер процесора, використання RAM, показують список усіх потоків додатків та дозволяють очищати пам'ять чи «вбивати» фонові процеси в один клік (через стандартні механізми Android API).
