# <h3 align="center"> Тема: “Створення скриптових сценаріїв та визначення апаратної конфігурації системи”
### Мета роботи: 
- Отримання практичних навиків роботи з командною оболонкою Bash.
- Знайомство знайомство з базовими діями при роботі зі скриптовими сценаріями.
### Словник термінів:
- Shell script — текстовий файл, який містить послідовність команд для виконання оболонкою (shell) і дозволяє автоматизувати повторювану роботу.
- $PATH — системна змінна оточення, яка містить перелік директорій (шляхів), де операційна система шукає виконувані файли та команди.
- Permission denied — помилка доступу («Доступ заборонено»), яка виникає, якщо файл скрипту не було позначено як виконуваний.
- chmod — команда в UNIX-подібних системах, яка використовується для зміни прав доступу до файлу (наприклад, для надання файлу статусу виконуваного).
- Shebang (hashbang / crunchbang) — перша лінія скрипту, яка починається з символів #! та вказує абсолютний шлях до інтерпретатора (наприклад, #!/bin/bash), який має виконувати цей файл.
- Interpreter — програма (інтерпретатор), яка зчитує та виконує код скрипту рядок за рядком (наприклад, Bash, Python, Perl).
- GNU nano — простий та зручний консольний текстовий редактор, який чудово підходить для редагування невеликих текстових файлів.
- vi / vim (VI improved) — надзвичайно потужний консольний текстовий редактор з великою кількістю функцій, але складний у вивченні.
- Copy buffer — буфер обміну (пам'ять редактора), куди тимчасово зберігається вирізаний або скопійований текст для подальшої вставки.
- Variables — змінні, які використовуються для збереження тимчасової інформації всередині скрипту.
- Conditionals — умовні конструкції (логіка), які дозволяють скрипту виконувати різні дії залежно від результатів перевірки певних умов.
- Loops — цикли, які дозволяють повторювати виконання однієї і тієї ж послідовності дій (команд) кілька разів поспіль.
### Завдання для попередньої підготовки:
##### 1.Скриптовий сценарій у командній оболонці:
Скриптовий сценарій (shell script) — це текстовий файл, який містить послідовність команд для командної оболонки (наприклад, Bash або Sh). Коли цей файл запускається, оболонка покроково виконує кожну команду, автоматизуючи повторювану роботу, заощаджуючи час користувача та гарантуючи точність виконання завдань.
##### 2.Створення, редагування та запуск скриптів:
- Створення та редагування: Скрипти створюються у будь-якому текстовому редакторі (наприклад, у простому консольному nano або потужному vim). Для створення файлу достатньо виконати команду nano myscript.sh, написати текст скрипту та зберегти файл.
- Підготовка до запуску: Щоб скрипт можна було запустити як самостійну програму, йому потрібно надати права на виконання за допомогою команди chmod +x myscript.sh. Якщо цього не зробити, система видасть помилку Permission denied.
- Запуск скрипту: Скрипт можна запустити двома способами:
   - Безпосередньо через інтерпретатор: bash myscript.sh або sh myscript.sh.
	- Напряму (якщо надано права на виконання): ./myscript.sh (префікс ./ вказує системі шукати файл у поточній директорії).
##### 3.Основні компоненти материнської плати:
- Процесорний роз'єм (Socket): Місце для встановлення центрального процесора (CPU).
- Чипсет (Північний та Південний мости або єдина мікросхема): Контролери, які забезпечують зв'язок між процесором, оперативною пам'яттю, відеокартою та периферійними пристроями.
- Слоти для оперативної пам'яті (DIMM slots): Роз'єми для встановлення модулів ОЗУ (RAM).
- Слоти розширення (PCI Express): Роз'єми для підключення відеокарт, звукових або мережевих плат.
- Мікросхема BIOS/UEFI: Енергонезалежна пам'ять, яка зберігає базове програмне забезпечення для початкового завантаження комп'ютера та тестування заліза.
- Роз'єми живлення: Основні порти для підключення кабелів від блока живлення.
- Інтерфейси накопичувачів (SATA, M.2 NVMe): Роз'єми для підключення жорстких дисків (HDD) та твердотільних накопичувачів (SSD).
- Порти введення-виведення (I/O panel): Зовнішні роз'єми на задній панелі (USB, HDMI, LAN, аудіо-виходи).
##### 4.Для яких пристроїв оперують поняттями MBR та GPT?
Поняттями MBR (Master Boot Record) та GPT (GUID Partition Table) оперують виключно для накопичувачів даних, таких як:
- Жорсткі диски (HDD)
- Твердотільні накопичувачі (SSD)
- Зовнішні диски та флеш-накопичувач
##### 5.Суть та призначення операції монтування:
Монтування (mounting) — це процес підключення файлової системи якогось пристрою (флешки, жорсткого диска, CD-роуму) до загального дерева каталогів операційної системи.
- В чому суть: В операційних системах на базі Linux чи Unix немає поняття «Диск D:» чи «Диск E:». Уся система — це одне велике дерево папок, яке починається з кореня (/). Коли ви підключаєте новий накопичувач, операційна система повинна «прив'язати» файлову систему цього накопичувача до якоїсь конкретної порожньої папки (точки монтування), наприклад, до /media/usb.
- Для чого це потрібно: Монтування необхідне для того, щоб користувач та програми отримали доступ до файлів на підключеному пристрої. Після завершення операції монтування файли на флешці стають доступними так, ніби вони просто лежать усередині папки, до якої її приєднали.
### Хід роботи:
#### 2.Тaблиця команд:
| Назва команди | Її призначення та функціональність |
| :--- | :--- |
| nano | Консольний текстовий редактор. Використовується для створення, відкриття та редагування файлів скриптів (наприклад, nano test.sh). |
| chmod | Зміна прав доступу до файлів. У лабораторній роботі застосовується з аргументом +x (наприклад, chmod +x test.sh) для надання файлу статусу виконуваного. |
| bash | Запуск інтерпретатора командної оболонки Bash. Застосовується для примусового виконання скрипту безпосередньо через інтерпретатор (bash test.sh). |
| sh | Запуск стандартної командної оболонки sh. Як і bash, може використовуватись для виконання скриптів (sh test.sh), ігноруючи рядок shebang. |
| cat | Виведення вмісту файлу на екран. У контексті скриптів використовується для перегляду коду сценарію без його запуску. |
| echo | Виведення рядка тексту або значень змінних на екран чи в термінал (наприклад, echo $PATH або echo "Hello World"). |
| test | Команда перевірки умов. Перевіряє типи файлів (наприклад, -f для звичайного файлу, -d для директорії), порівнює числа (-eq, -ne) або текстові рядки. |
| lscpu | Виведення детальної інформації про архітектуру центрального процесора (CPU), кількість ядер, потоків, кеш-пам'ять та підтримувані технології. |
| free | Відображення обсягу вільної та використаної оперативної пам'яті (RAM), а також простору підкачки (Swap) у системі. |
| lspci | Виведення списку всіх пристроїв, підключених до системних шин PCI/PCIe (відеокарти, мережеві адаптери, контролери). Опція -k показує використовувані драйвери ядра. |
| lsusb | Виведення переліку всіх підключених до комп'ютера USB-пристроїв та USB-контролерів (флешки, миші, клавіатури). |
| lsmod | Відображення списку модулів (драйверів) ядра Linux, які завантажені в оперативну пам'ять на цей момент. |
| fdisk | Утиліта для керування таблицями розділів на жорстких дисках та SSD. Опція fdisk -l використовується для неінтерактивного виведення списку всіх дисків та їх розділів. |
