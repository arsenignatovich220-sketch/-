### Мета роботи: 
- Отримання практичних навиків роботи з командною оболонкою Bash.
- Знайомство з базовими командами для архівування та стиснення даних.
- Знайомство з базовими діями при роботі з текстом у терміналі.
### Словник термінів:
- Compression — процес зменшення розміру файлу на диску за допомогою математичних розрахунків та алгоритмів.
- Archiving — об'єднання групи пов'язаних файлів у один для зручності зберігання, копіювання чи передачі, із збереженням прав доступу та метаданих.
- Lossy compression — стиснення із втратою даних (наприклад, MP3 або JPEG), за якого частина інформації видаляється безповоротно, а оригінал неможливо відновити.
- Lossless compression — стиснення без втрати даних, яке дозволяє зменшити розмір файлу і згодом повністю відновити його оригінальний стан.
- Adaptive compression — сучасний підхід, за якого утиліта аналізує файл "на льоту" і динамічно оновлює словник повторюваних значень під час роботи.
- Tar file — формат архіву в Linux, який історично використовувався для запису на магнітні стрічки, а зараз слугує для зручного керування групами файлів.
- gzip — класичний інструмент стиснення (з 1992 року), який працює дуже швидко та споживає мінімум пам'яті.
- bzip2 — традиційна альтернатива gzip, яка стискає файли сильніше, але працює повільніше.
- xz — сучасна утиліта (з 2009 року), що забезпечує найвищий рівень стиснення, але вимагає багато часу та оперативної пам'яті.
- DEFLATE — алгоритм стиснення, який використовує утиліта gzip (також застосовується в PNG, HTTP, SSH).
- Burrows-Wheeler — складніший алгоритм, на якому базується робота утиліти bzip2.
- LZMA2 — потужний алгоритм, який використовується в утиліті xz для досягнення максимального стиснення.
- -r (recursive) — прапорець gzip для рекурсивного спуску по директорії та стиснення кожного файлу окремо.
- -l (list) — параметр для виведення статистики про стиснений файл (розмір до і після, коефіцієнт стиснення).
- -c (stdout) — прапорець для перенаправлення результату стиснення у стандартний вивід (наприклад, для передачі через конвеєр).
- -d (decompress) — універсальний прапорець для розпакування файлів (спільний для gzip, bzip2 та xz).
- -s (small) — прапорець у bzip2, який зменшує використання оперативної пам'яті вдвічі за рахунок дещо гіршого стиснення.
- -e (extreme) — спеціальний режим в xz для максимального стиснення великих файлів без урахування витрат часу та пам'яті.
### Завдання для попередньої підготовки:
#### 1)Команди архівації та стиснення (tar, xz, zip, bzip2, gzip)
- tar (Tape Archive)
   - Призначення: Об'єднує багато файлів та каталогів в один файл (архів) із збереженням прав доступу та структури. Сам по собі не стискає дані, але вміє автоматично викликати інші утиліти (gzip, bzip2, xz) для стиснення.
   - Параметри:
		- -c (create) — створити новий архів.
		- -x (extract) — розпакувати архів.
		- -v (verbose) — показувати хід виконання (список файлів).
		- -f (file) — вказати ім'я файлу архіву (завжди ставиться останнім перед ім'ям файлу).
		- -z, -j, -J — викликати відповідно gzip, bzip2 або xz для стиснення.

-  gzip (GNU zip)
   - Призначення: Швидке та класичне стиснення окремих файлів. Замінює оригінальний файл файлом із розширенням .gz.
   - Параметри:
	   - -d — декомпресія (розпакування).
	   - -c — вивести результат у стандартний потік (залишає оригінал).
	   - -9 — максимальне (але найповільніше) стиснення.
-  bzip2
   - Призначення: Традиційна альтернатива gzip. Стискає краще за gzip, але працює повільніше. Створює файли .bz2.
   - Параметри:
		- -d — декомпресія.
		- -s (small) — режим економії оперативної пам'яті.

-  xz
   - Призначення: Сучасний інструмент для максимального стиснення даних. Ідеальний для дистрибуції ПЗ. Створює файли .xz.
   - Параметри:
		- -d — декомпресія.
		- -e (extreme) — режим екстремального стиснення.

-  zip
   - Призначення: Створює сумісні з Windows архіви, які одночасно і об'єднують файли, і стискають їх.
   - Параметри:
		- -r — рекурсивне стиснення (для архівації папок).
		- -e — зашифрувати архів паролем.
##### 
Як їх встановити?

У більшості дистрибутивів Linux (tar, gzip, bzip2, xz) встановлені за замовчуванням. Якщо якась утиліта відсутня, її можна встановити через менеджер пакетів:
- Ubuntu / Debian / Mint: sudo apt update && sudo apt install tar gzip bzip2 xz-utils zip unzip
- CentOS / RHEL / Fedora: sudo dnf install tar gzip bzip2 xz zip unzip
#### 2)Три приклади архівації та стиснення різними командами:
##### 1.Створення архіву папки за допомогою tar та gzip (найпопулярніший метод):
tar -czvf archive.tar.gz /path/to/folder
##### 2.Максимальне стиснення великого файлу за допомогою xz:
xz -9 file.txt
##### 3.Створення ZIP-архіву папки з паролем (для сумісності з Windows):
zip -re secure_archive.zip /path/to/folder
#### 3)Команди перегляду текстових файлів (cat, less, more, head, tail)
- cat (Concatenate)
  - Призначення: Виводить увесь вміст файлу в терміналі від початку до кінця без зупинок. Також використовується для склеювання файлів.
	- Параметри: -n — нумерувати всі рядки виводу.
- more
  - Призначення: Посторінковий перегляд тексту. Дозволяє гортати файл лише вперед (за допомогою клавіші Space).
- less
   - Призначення: Покращена версія more. Дозволяє гортати файл як вперед, так і назад (стрілками), не завантажує весь файл у пам'ять (працює миттєво з гігабайтними логами) та підтримує пошук.
	  - Параметри: -N — показувати номери рядків.
- head
   - Призначення: Виводить перші рядки файлу (за замовчуванням — 10 рядків).
	  - Параметри: -n [кількість] — вказати точну кількість рядків (наприклад, head -n 5 file.txt).
- tail
   - Призначення: Виводить останні рядки файлу (за замовчуванням — 10). Дуже часто використовується для моніторингу логів систем у реальному часі.
	  - Параметри:
		 - -n [кількість] — кількість рядків з кінця.
		 - -f (follow) — тримати файл відкритим і виводити нові рядки в міру їх появи.
##### Як їх встановити?

Усі ці команди є базовою частиною будь-якої Linux-системи (пакет coreutils та less) і завжди встановлені за замовчуванням.
#### 4)Канали, потоки та фільтри в командній оболонці:
##### 1. Стандартні потоки (Streams)
Кожен процес в Linux автоматично відкриває три потоки даних:
- stdin (Стандартний ввід / 0): Потік, звідки програма чекає дані (зазвичай клавіатура).
- stdout (Стандартний вивід / 1): Потік, куди програма відправляє результати своєї роботи (зазвичай екран).
- stderr (Стандартний вивід помилок / 2): Окремий потік для повідомлень про помилки (теж виводиться на екран, але відокремлений від корисних даних).
##### 2. Канали або конвеєри (Pipes)
Символ вертикальної риски | (pipe) дозволяє зв'язати стандартний вивід (stdout) однієї команди безпосередньо зі стандартним вводом (stdin) іншої команди. Данні передаються по ланцюжку без створення тимчасових файлів на диску.
##### 3.Фільтри (Filters)
Фільтр — це програма, яка приймає дані на свій stdin, певним чином їх трансформує (фільтрує, сортує, обрізає) і видає результат на stdout. Приклади фільтрів: grep, sort, head, tail, wc.
###### Приклад роботи всього ланцюжка:
cat /var/log/nginx/access.log | grep "404" | wc -l
#### 5)Призначення команди grep
grep (Global Regular Expression Print) — це один із найпотужніших інструментів у Linux, призначений для пошуку тексту всередині файлів або у вхідному потоці даних за заданим шаблоном або регулярним виразом.
Команда сканує текст рядок за рядком і виводить на екран тільки ті рядки, які містять шукане слово чи збіг.

#### 3.Команда tar та її застосування:
##### 1) Створити звичайний файл з розширенням .tar (без стиснення)
Щоб просто об'єднати файли або папку в один архів без зменшення його розміру, використовується прапорець -c (create):
tar -cvf archive.tar /path/to/folder
##### 2)Створити файл .tar з декількох файлів і каталогів одночасно
Ви можете передати команді tar список із кількох різних елементів (файлів та папок), розділяючи їх пробілом:
tar -cvf multi_archive.tar file1.txt file2.jpg /path/to/directory1 /another/folder
##### 3) Перегляд вмісту файлу архіву (без розпакування)
Щоб зазирнути всередину створеного архіву та перевірити список файлів, не витягуючи їх на диск, використовуйте прапорець -t (list):
tar -tvf archive.tar
##### 4) Витягти (розпакувати) вміст файлу .tar
Для вилучення файлів з архіву у вашу поточну робочу директорію використовується прапорець -x (extract):
tar -xvf archive.tar
##### 5) Створити архівний файл .tar, стиснений за допомогою bzip2
Щоб зменшити розмір архіву за допомогою алгоритму bzip2, додається прапорець -j. Файлу прийнято давати розширення .tar.bz2 або .tbz2:
tar -cjvf archive.tar.bz2 /path/to/folder
##### 6) Витягти вміст файлу tar bzip2
Для розпакування файлу .tar.bz2 використовується та сама комбінація для вилучення разом із прапорцем -j:
tar -xjvf archive.tar.bz2
##### 7)Створити архівний .tar файл, стиснений за допомогою gzip
Для швидкого стиснення за допомогою популярного алгоритму gzip використовується прапорець -z. Файл отримує розширення .tar.gz або .tgz:
tar -czvf archive.tar.gz /path/to/folder
##### 8)Витягти вміст файлу tar gzip
Щоб розпакувати стиснений gzip архів назад у файлову систему, додайте прапорець -z до команди витягування:
tar -xzvf archive.tar.gz
#### 4.Як буде відбуватись перенаправлення потоків виведення в bash для наступних дій з командами (позначено як cmd) та файлами (позначено як file):
| Команда | Що виконує команда? |
| :--- | :--- |
| cmd 1> file | Перенаправляє стандартний вивід (stdout) команди cmd у файл file. Якщо файл вже існує, його вміст буде перезаписано. |
| cmd > file | Діє аналогічно до cmd 1> file. Скорочений запис для перенаправлення стандартного виводу (stdout) у файл file із перезаписом вмісту. |
| cmd 2> file | Перенаправляє тільки потік помилок (stderr) команди cmd у файл file із перезаписом. Звичайний успішний вивід (stdout) залишається на екрані. |
| cmd >> file | Перенаправляє стандартний вивід (stdout) команди cmd у файл file, але не видаляє старі дані, а дописує (додає) нові в кінець файлу. |
| cmd &> file | Одночасно перенаправляє і стандартний вивід, і потік помилок (stdout + stderr) команди cmd в один файл file із перезаписом його вмісту. |
| cmd > file 2>&1 | Спочатку спрямовує stdout у файл file, а потім перенаправляє stderr (дескриптор 2) туди ж, куди вказує stdout (дескриптор 1). У результаті і звичайний вивід, і помилки записуються у файл file із перезаписом. |
| cmd >> file 2>&1 | Діє аналогічно до попередньої команди, але дані (як успішні, так і помилки) дописуються в кінець файлу file, не видаляючи його попередній вміст. |
| cmd 2>&1 > /dev/null | Спрямовує потік помилок stderr туди, куди на даний момент вказує stdout (на екран), а потім сам stdout перенаправляє в "чорну діру" /dev/null. У результаті: помилки виведуться на екран, а успішний результат команди зникне. | 
| cmd 2> /dev/null | Перенаправляє потік помилок stderr у пристрій /dev/null. Це дозволяє повністю приховати/ігнорувати всі повідомлення про помилки під час виконання команди. |
| cmd1 | cmd2 | Створює конвеєр (канал). Стандартний вивід (stdout) першої команди cmd1 передається безпосередньо на стандартний вхід (stdin) другої команди cmd2. |
| cmd1 2>&1 | cmd2 | Спрямовує помилки (stderr) команди cmd1 у її ж стандартний вивід, після чого весь об'єднаний потік (і успішний результат, і помилки) передається через конвеєр на вхід команди cmd2. |
#### 5.Розгляньте наведені нижче приклади та поясніть, що виконують дані команди та який тип перенаправлення потоків вони використовують:

| echo "It is a new story." > story | Записує текст у файл story, повністю перезаписуючи його старий вміст. | Стандартний вивід (stdout) із перезаписом. |
| date > date.txt | Записує поточну системну дату та час у файл date.txt із перезаписом. | Стандартний вивід (stdout) із перезаписом. |
| cat file1 file2 file3 > bigfile | Об'єднує вміст трьох файлів в один новий великий файл bigfile | Стандартний вивід (stdout) із перезаписом. |
| ls -l >> directory | Дописує детальний список файлів у кінець файлу directory без видалення старих даних. | Стандартний вивід (stdout) у режимі додавання. |
| sort < file1_unsorted > file2_sorted | Бере дані з невідсортованого файлу, сортує їх та записує у новий файл. | Одночасно стандартний ввід (stdin) та вивід (stdout). | 
| find -name '*.txt' > file.txt 2> /dev/null | Шукає тексти: успішні результати пише у файл, а помилки доступу повністю приховує. | Роздільне перенаправлення: stdout у файл, stderr у порожнечу. |
| cat file1_unsorted  sort > file2_sorted | Читає файл, передає текст через канал на сортування та зберігає результат. | Конвеєр (канал pipe) та перенаправлення stdout із перезаписом. |
| cat myfile  grep student  wc -l | Читає файл, відбирає рядки зі словом "student" та підраховує їхню підсумкову кількість. | Ланцюжок конвеєрів (два канали pipe) без файлового виводу. |
### Контрольні запитання:
#### 1. Порівняльна характеристика процесів стискання та архівування
Архівування та стискання — це два абсолютно різних етапи обробки даних, хоча в повсякденній роботі вони часто виконуються одночасно.
Архівування (Archiving) — це процес об'єднання багатьох окремих файлів і папок в один єдиний файл (архів). Його головна мета — не зменшити розмір, а навести лад: зберегти складну структуру каталогів, права доступу до файлів (POSIX-дозволи) та метадані (наприклад, час створення), щоб дані було зручно переносити чи копіювати. Розмір архіву зазвичай дорівнює сумі розмірів усіх файлів, що в нього увійшли. Основним інструментом в Linux для цього є команда tar.
Стискання (Compression) — це процес зменшення фізичного розміру файлу на жорсткому диску за допомогою спеціальних математичних алгоритмів. Програма шукає в тексті чи коді повторювані фрагменти й замінює їх короткими унікальними маркерами. Стискання виконується заради економії місця або для прискорення передачі даних через інтернет. Прикладами інструментів для стискання є команди gzip, bzip2 та xz.
#### 2. Інші програми для стискання та архівування в Linux
Окрім базових інструментів, що розглядалися в лабораторній роботі, в ОС Linux часто використовуються такі програмні засоби:
- 7z (7-Zip) — популярна кросплатформова утиліта. Вона забезпечує один із найвищих рівнів стискання завдяки власному відкритому алгоритму LZMA/LZMA2. Окрім рідного формату .7z, вона легко працює з архівами .zip, .rar та багатьма іншими.
- zstd (Zstandard) — надсучасний алгоритм, створений компанією Meta (Facebook). Його головна особливість — неймовірна швидкість розпакування та гнучкий баланс між швидкістю стискання та розміром файлу. Він зараз активно впроваджується в Linux за замовчуванням (наприклад, для стискання системних пакетів оновлень).
- pigz (Parallel Implementation of GZip) — це спеціальна модифікація класичної команди gzip. Звичайний gzip під час роботи використовує лише одне ядро процесора, тоді як pigz розпаралелює задачу на всі доступні ядра, що робить процес стискання великих файлів у рази швидшим.
- lbzip2 та pbzip2 — аналогічні багатопотокові версії для утиліти bzip2. Вони дозволяють обійти головний мінус bzip2 — його повільність на сучасних багатоядерних комп'ютерах.
#### 3. Порівняння алгоритмів стиснення в Linux
В Linux-системах історично склалося протистояння кількох алгоритмів, кожен з яких має свої компроміси:
- Алгоритм DEFLATE (використовується в gzip та zip) — побудований на поєднанні кодування LZ77 та Хаффмана. Це найстаріший та найбільш сумісний метод.
- Алгоритм Burrows-Wheeler (використовується в bzip2) — використовує блочне сортування тексту для пошуку однакових послідовностей. Стискає дані краще, ніж DEFLATE.
- Алгоритм LZMA / LZMA2 (використовується в xz та 7-zip) — використовує ланцюжкове кодування з марковськими моделями, що забезпечує найвищу ефективність упаковки.
##### Підсумок порівняння:
- Найшвидшим серед класичних є алгоритм DEFLATE (gzip), а серед сучасних — Zstandard, який розпакує дані майже миттєво.
- Найефективнішим (забезпечує найменший розмір файлу) є алгоритм LZMA2 (xz). Проте за мінімальний розмір доводиться платити часом: процес стискання з максимальним прапорцем -9 є дуже повільним та вимагає багато оперативної пам'яті.
#### 4.Програмні засоби для мобільних телефонів
На смартфонах користувачам також часто доводиться працювати з архівами (наприклад, для надсилання багатьох фото одним файлом або розпакування завантажених документів):
- Для ОС Android:
   - ZArchiver — найпотужніший мобільний архіватор. Він підтримує величезну кількість форматів (включаючи .zip, .7z, .rar, .tar.gz), дозволяє створювати зашифровані архіви та розбивати великі файли на частини (томи).
	- RAR від RARLAB — офіційний мобільний аналог відомої програми WinRAR, який ідеально працює з форматами .rar та .zip.
	- Вбудовані менеджери файлів (як-от Files від Google або провідники від Samsung/Xiaomi) мають базову функцію: вони можуть запакувати або розпакувати простий .zip без стороннього софту.
#### 5. Програмні засоби в ОС сімейства Windows
У системах Windows робота з архівами побудована навколо графічного інтерфейсу (GUI) та контекстного меню миші:
- Вбудований архіватор Windows (Провідник) — забезпечує базову роботу із файлами .zip прямо "з коробки". В останніх версіях Windows 11 розробники додали також початкову підтримку розпакування .rar, .7z та .tar.gz. Має мінімум налаштувань, але не потребує встановлення програм.
- 7-Zip — абсолютно безкоштовна програма з відкритим сирцевим кодом. Вважається найкращим вибором для Windows. Вона має свій формат .7z, працює надзвичайно швидко, не набридає рекламою та інтегрується в Провідник.
- WinRAR — легендарний умовно-безкоштовний архіватор, який використовує закритий комерційний формат .rar. Його головна перевага — вміння додавати в архів інформацію для відновлення пошкоджених файлів. Проте програма постійно просить купити ліцензію після завершення пробного періоду.
- WinZip — комерційний інструмент, який колись був лідером, але зараз втратив позиції через високу вартість та наявність безкоштовних конкурентів.
##### Порівняння: 7-Zip виграє за рахунок безкоштовності та швидкості, тоді як WinRAR залишається популярним завдяки звичці користувачів та надійності формату .rar у захисті від пошкодження даних.
#### 6. Використання стиснення та архівування в задачах системного адміністрування
Стиснення та архівування є критично важливими для створення резервних копій:
- Збереження метаданих: Команда tar об'єднує конфігураційні файли чи бази даних в один файл, чітко зберігаючи права доступу користувачів Linux. Якщо просто скопіювати файли, ці права можуть скинутися, і система після відновлення не запуститься.
- Економія місця: Текстові бази даних або системні налаштування стискаються в кілька разів, що дозволяє тримати на сервері бекапи за багато місяців без переповнення дисків.
- Економія мережевого трафіку: Стиснутий архів важить значно менше, тому його набагато швидше передавати через інтернет на віддалені хмарні сховища (наприклад, через утиліту rsync).
##### Інші задачі адміністрування
- Ротація системних логів (служба logrotate): Журнали подій Linux (/var/log/) щодня збільшуються. Щоб диск не переповнився, спеціальний демон автоматично архівує та стискає за допомогою gzip старі логи за минулі тижні чи місяці.
- Розгортання програмного забезпечення: Всі інсталяційні пакети програм в Linux (формати .deb для Ubuntu чи .rpm для RedHat) насправді є архівами, стиснутими через xz чи zstd. Це дозволяє користувачам швидко завантажувати їх з репозиторіїв.
- Міграція проектів: Коли адміну потрібно перенести сайт чи базу даних на інший сервер, він пакує всі папки в один файл за допомогою tar -czvf, переносить його та розпаковує на новому місці, замість того, щоб годинами копіювати тисячі дрібних картинок чи скриптів.
#### 7. Призначення директорії (файлу) /dev/null
Файл /dev/null в Linux — це особливий віртуальний пристрій, який у середовищі системних адміністраторів називають "чорною дірою" або "поглиначем даних".
Його головне призначення — безповоротно знищувати будь-які дані, які в нього записують. Коли ви перенаправляєте туди потік інформації (наприклад, за допомогою оператора > /dev/null), операційна система миттєво стирає ці дані на рівні ядра. При цьому комп'ютер не витрачає ресурси процесора чи місце на жорсткому диску. Якщо спробувати щось прочитати з файлу /dev/null, він одразу поверне пусту відповідь (кінець файлу).
##### Навіщо це потрібно?
Найчастіше адміни використовують його для очищення екрана від зайвої інформації під час написання скриптів. Наприклад, якщо команда пошуку find / -name "*.txt" 2> /dev/null натрапляє на закриті системні папки, вона генерує сотні помилок "Permission denied" (Доступ заборонено). Перенаправлення потоку помилок 2> у /dev/null повністю приховує цей інформаційний шум, і на екран виводяться лише корисні результати пошуку.
