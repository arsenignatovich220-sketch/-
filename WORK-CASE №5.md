### Словник термінів:
- Everything is a file (Усе є файлом) — фундаментальний принцип архітектури UNIX/Linux, згідно з яким взаємодія з будь-якими апаратними пристроями, процесами та мережевими потоками відбувається через читання або запис у спеціальні файли.
- Kernel (Ядро) — центральна, найважливіша частина операційної системи, яка забезпечує взаємодію між апаратним забезпеченням (залізом) та програмним забезпеченням комп'ютера.
- Driver / Kernel Module (Драйвер / Модуль ядра) — спеціальний програмний код, який розширює функціонал ядра та дозволяє операційній системі взаємодіяти з конкретним апаратним пристроєм.
- Block Device (Блочний пристрій) — пристрій (наприклад, флешка чи жорсткий диск), який передає та зберігає дані фіксованими порціями (блоками) і підтримує довільний доступ до інформації.
- Character Device (Символьний пристрій) — пристрій (наприклад, принтер чи клавіатура), який передає дані послідовно, як неперервний потік байтів (символів), без фіксації в блоки.
- Mounting (Монтування) — процес логічного підключення файлової системи пристрою (наприклад, розділу флешки) до певної папки в єдиному дереві каталогів Linux для отримання доступу до його файлів.
- Mount Point (Точка монтування) — порожня директорія (папка) в існуючому дереві каталогів Linux, до якої «прикріплюється» файлова система нового пристрою.
- Unmounting (Розмонтування) — процес безпечного програмного відключення пристрою від дерева каталогів, під час якого завершуються всі операції запису та очищується кеш даних перед фізичним витяганням.
- Virtual File System (VFS) (Віртуальна файлова система) — рівень абстракції ядра Linux, який дозволяє користувачу та програмам однаково працювати з різними типами файлових систем та пристроїв (через каталог /dev).
- fstab (File System Table) — конфігураційний файл у Linux (шлях: /etc/fstab), що містить список дисків і розділів, які мають автоматично монтуватися в систему під час кожного завантаження комп'ютера.
- udev — підсистема ядра Linux, яка керує файлами пристроїв у каталозі /dev, динамічно реагуючи на підключення або відключення «заліза» (наприклад, USB-пристроїв).
- CUPS (Common Unix Printing System) — модульна система друку для UNIX-подібних ОС, яка працює як фонова служба (демон), керує чергами друку, драйверами та конвертує документи у зрозумілий для принтера формат.
- PPD (PostScript Printer Description) — файли опису принтера, які містять інформацію про його технічні можливості, підтримувані шрифти, формати паперу та специфічні команди для правильної роботи через CUPS.
- GUI (Graphical User Interface) — графічний інтерфейс користувача, який дозволяє взаємодіяти з ОС за допомогою вікон, кнопок, миші та ярликів.
- CLI / Terminal (Інтерфейс командного рядка / Термінал) — текстовий інтерфейс керування комп'ютером, де всі команди системі вводяться вручну з клавіатури.
#### 1.
#### 1)При роботі з персональним комп’ютером дуже часто виникає необхідність підключати периферійне обладнання. На прикладі принтера та флешки опишіть який механізм має ОС Linux для роботи з ними:
##### Загальний механізм: від заліза до користувача
Будь-яке підключення пристрою в Linux проходить через такі етапи:
- Ядро (Kernel) та Драйвери: Ядро Linux виявляє пристрій на апаратному рівні (наприклад, через шину USB). Для кожного пристрою завантажується відповідний модуль (драйвер).
- Віртуальна файлова система /dev: Для взаємодії з пристроєм ядро створює спеціальний файл символьного або блочного пристрою в директорії /dev. Запис або читання з цього файлу означає передачу даних самому пристрою.
- Демони (Системні служби): Спеціальні фонові програми (демони) «слухають» появу нових пристроїв та налаштовують їх для користувача.
##### 1. Робота з флеш-накопичувачем (Блочний пристрій)
Флешка належить до блочних пристроїв (дані передаються фіксованими блоками). Механізм роботи з нею виглядає так:
- Визначення пристрою: Сид підсистеми ядра udev помічає підключення USB-накопичувача.
- Створення файлу пристрою: В директорії /dev з'являється новий файл. Зазвичай це /dev/sda або /dev/sdb (де sd означає SCSI-диск, а буква — порядковий номер пристрою). Розділи на флешці маркуються цифрами, наприклад: /dev/sdb1.
- Монтування (Mounting): Щоб користувач міг читати чи записувати файли, файлову систему флешки потрібно «прикріпити» до загального дерева каталогів Linux.
  - У сучасних графічних оболонках (Ubuntu, Mint тощо) за це відповідає демон udisks. Флешка монтується автоматично в каталог /media/імя_користувача/назва_флешки.
  - У консолі це робиться командою: mount /dev/sdb1 /mnt.
##### 2. Робота з принтером (Символьний пристрій / Потокова служба)
Принтер — це символьний пристрій (дані передаються послідовним потоком байтів). Механізм взаємодії з ним складніший через потребу в конвертації форматів:
- Визначення та файл пристрою: При підключенні через USB ядро створює файл пристрою, наприклад /dev/usb/lp0.
- Служба друку CUPS: Головним механізмом керування друком в Linux є CUPS (Common Unix Printing System). Цей демон працює у фоновому режимі.
- Драйвери та PPD: CUPS використовує файли опису PostScript-принтерів (PPD) та специфічні драйвери (наприклад, від виробника або відкриті проекти на кшталт Gutenprint). Вони потрібні, щоб перекласти документ (наприклад, PDF або сторінку тексту) у формат растрових команд, які розуміє конкретна модель принтера.
- Черга друку: Коли ви натискаєте «Друк», документ потрапляє в чергу подій CUPS, яка покроково відправляє дані у файл пристрою /dev/usb/lp0.
#### 2)В чому суть операції монтування, для чого вона використовується та як?
Суть операції монтування (mounting) в ОС Linux полягає в тому, що вона пов’язує файлову систему якогось пристрою (флешки, жорсткого диска, CD-рома) з конкретною директорією в загальному дереві каталогів Linux.
##### Для чого використовується монтування?
Монтування потрібне для:
- Доступу до накопичувачів: Без монтування ОС Linux знає, що пристрій підключено (бачить файл пристрою, наприклад /dev/sdb1), але не дозволяє читати чи записувати туди файли.
- Об’єднання різних дисків: Ви можете підключити швидкий SSD для системи в корінь /, а великий і повільний HDD змонтувати в каталог /home, де зберігаються важкі файли користувачів. Для користувача це виглядатиме як одна цілісна система.
- Підключення мережевих ресурсів: Можна змонтувати папку з іншого комп'ютера в мережі (через NFS або Samba) у локальну папку, і робота з нею нічим не відрізнятиметься від роботи зі звичайним локальним диском.
##### Як відбувається монтування?
Коли ви вставляєте флешку у графічному інтерфейсі (Ubuntu, Mint, Fedora тощо), спеціальна системна служба (udisks) автоматично створює папку та монтує туди пристрій.
- Зазвичай це шлях: /media/ім'я_користувача/назва_флешки/
- Ви просто відкриваєте її через провідник, а при витяганні натискаєте кнопку «Витягти» (це операція розмонтування або umount, яка гарантує, що всі дані встигли записатися з кешу на флешку).
#### 3)В чому різниця при роботі з периферією у ОС Linux та ОС Windows?
| Критерій | ОС Windows | ОС Linux |
| :--- | :--- | :--- |
| Головний принцип | «Усе є об'єктом / сутністю». Пристрої керовані через API та реєстр. | «Усе є файлом». Будь-яка залізяка — це просто спеціальний файл у /dev. |
| Доступ до накопичувачів | Кожен диск має свою букву (C:, D:, E:). | Єдине дерево каталогів (/). Флешки монтуються в папки (наприклад, /media/usb). |
| Драйвери | Завантажуються окремо (як .exe файли від виробника) або через Windows Update. | Більшість драйверів вже вшиті в ядро. Пристрої працюють «з коробки» (Plug and Play). |
| Друк (Принтери) | Через службу Spooler та графічні драйвери виробника. | Через єдину стандартизовану службу CUPS та PostScript описи (PPD). |
| Керування пристроями | Графічний «Диспетчер пристроїв» (Device Manager). | Консольні утиліти (lsblk, lspci, lsusb) та правила udev. |

#### Методика виконання:
##### 1)Попереднє налаштування віртуальної машини (VirtualBox)
Щоб віртуальна машина взагалі «побачила» ваші фізичні пристрої, їх потрібно «прокинути» через налаштування гіпервізора.

- Для принтера: Якщо принтер підключений через USB, зробіть те саме в меню USB. Якщо він мережевий, переконайтеся, що в налаштуваннях мережі ВМ вибрано режим «Мережевий міст» (Bridged Adapter).
- Запустіть віртуальну машину з Linux.
##### 2)Копіювання файлу з флешки
- Відкрийте графічний файловий менеджер (програму «Файли» або Nautilus).
- На лівій панелі у вкладці «Пристрої» або «Місця» знайдіть назву вашої флешки та натисніть на неї (вона змонтується автоматично).
- Знайдіть потрібний файл (наприклад, document1.pdf), натисніть на нього правою кнопкою миші → Копіювати.

- Відкрийте скопійований файл document1.pdf подвійним кліком (він відкриється у стандартному переглядачі документів).
- Натисніть комбінацію клавіш Ctrl + P або знайдіть іконку принтера (меню «Друк»).
- У списку принтерів виберіть ваш принтер. Якщо реального принтера немає, виберіть віртуальний пункт «Друк у файл (PDF)» (це дозволить імітувати процес друку).
- Натисніть кнопку Друк.
### Висновок:
In this laboratory work, I have comprehensively analyzed the architectural principles and practical mechanisms that the Linux operating system utilizes to manage peripheral equipment, specifically focusing on a USB flash drive and a printer. Through this investigation, I have deeply explored the core UNIX philosophy that "everything is a file," which serves as the foundation for hardware interaction in Linux. This approach unifies the management of diverse hardware by representing each physical device as a special file within the virtual file system located in the /dev directory.
The practical part of the work allowed me to clearly differentiate between the two main classes of peripheral devices based on their data transmission methods:
- Storage Devices (Block Devices): Using a USB flash drive (represented as /dev/sdX), I mastered the concept of mounting, which is the process of attaching an external file system to a specific mount point within the single, unified Linux directory tree (/). This contrasted sharply with the Windows operating system, which assigns separate drive letters to each storage unit.
- Printing Devices (Character Devices): Using a printer (represented as /dev/usb/lpX), I examined the operation of CUPS (Common Unix Printing System). This background service manages the sequential stream of bytes, schedules print queues, and uses PPD files to translate documents into hardware-readable commands.
