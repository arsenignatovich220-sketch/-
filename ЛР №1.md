### Мета роботи:
##### 1. Знайомство з гіпервізорами різного типу, віртуалізацією при роботі з операційними системами.
##### 2. Знайомство з основними видами сучасних ОС, короткий огляд їх можливостей.
### Завдання для попередньої підготовки.
# <h3 align="center"> Словник Термінів
- Virtual machine (VM) — віртуальна машина; програмна система, яка імітує роботу реального фізичного комп'ютера.
- Virtualization — віртуалізація; технологія створення віртуального представлення фізичних ресурсів (ОС, серверів, сховищ даних).
- Virtual machine monitor (VMM) / Hypervisor — монітор віртуальних машин / гіпервізор; спеціалізоване програмне забезпечення або модуль, що створює, запускає та контролює віртуальні машини.
- Host operating system (Host OS) — хостова (головна) операційна система; ОС, яка встановлена безпосередньо на фізичному обладнанні та поверх якої працює гіпервізор 2 типу.
- Guest operating system (Guest OS) — гостьова операційна система; ОС, яка встановлюється та працює всередині віртуальної машини.
- Bare metal — «голе залізо»; фізичне комп'ютерне обладнання (процесор, пам'ять, диски) без попередньо встановленої операційної системи чи програм.
- Type 1 hypervisor — гіпервізор 1 типу; тип архітектури, де гіпервізор встановлюється безпосередньо на фізичне обладнання (bare metal) без хостової ОС.
- Binary translation — бінарна трансляція; технологія покращення продуктивності ранніх віртуальних машин шляхом перекладу блоків коду «на льоту» та їх кешування.
- Virtualizable CPU — віртуалізований центральний процесор; процесор, архітектура якого дозволяє коректно перехоплювати привілейовані інструкції гостьової ОС для їх програмної емуляції.
- Privileged instruction — привілейована інструкція; команда процесора (наприклад, введення-виведення або зміна стану системи), яку дозволено виконувати лише ядру операційної системи.
- Shared hosting — спільний (віртуальний) хостинг; вид хостингу, де багато користувачів ділять ресурси одного вебсервера та мають лише обліковий запис без контролю над системним ПЗ.
- Dedicated hosting — виділений хостинг; вид хостингу, де клієнту надається в оренду окремий фізичний сервер, що забезпечує максимальну гнучкість, але є дорожчим.
- Java Virtual Machine (JVM) — віртуальна машина Java; програмне середовище (віртуальна комп'ютерна архітектура), призначене для виконання універсального байт-коду Java на будь-якому пристрої.
### Поняття гіпервізору та його типи
Гіпервізор  — це спеціалізоване програмне забезпечення, яке керує фізичними ресурсами комп'ютера (процесор, пам'ять, диски) та розподіляє їх між кількома ізольованими віртуальними машинами. Завдяки йому на одному фізичному комп’ютері можна одночасно запускати абсолютно різні операційні системи (наприклад, Windows, Linux, macOS), які працюють незалежно і не заважають одна одній.
### Типи Гіпервізорів
Гіпервізор 1 типу- встановлюється і функціонує безпосередньо на фізичному обладнанні комп'ютера без використання будь-якої проміжної операційної системи. Він самостійно виконує роль базової системи, бере на себе повний контроль над процесором, оперативною пам'яттю та дисками, а також виділяє ці ресурси створеним віртуальним машинам. Завдяки відсутності додаткових програмних шарів він забезпечує максимальну швидкість роботи, високу безпеку та ізоляцію, тому є основним стандартом для великих серверів, корпоративних дата-центрів і хмарних інфраструктур, де критично важливою є висока продуктивність.
#
Гіпервізор 2 типу- працює виключно як звичайний прикладний додаток, який користувач запускає всередині вже встановленої на комп'ютері хостової операційної системи. Для виконання будь-яких дій із процесором чи збереження даних на диск цей гіпервізор змушений постійно звертатися до ядра та файлової системи головної ОС, що створює помітні затримки та знижує загальну ефективність роботи. Проте він є надзвичайно зручним у повсякденному використанні, легко встановлюється на звичайні персональні комп'ютери та ідеально підходить для розробників і тестувальників, яким потрібно швидко запускати різні операційні системи на одному робочому місці.
### Характеристика гіпервізора Hyper-V:
Hyper-V — це апаратний гіпервізор 1 типу від компанії Microsoft, який інтегровано в операційні системи Windows Server та професійні версії Windows для настільних ПК.
#### Основні компоненти архітектури Hyper-V
- Батьківський розділ (Parent Partition) — головна керувальна віртуальна машина, яка створюється автоматично при старті системи; вона містить хостову ОС Windows, стек віртуалізації та надає доступ до фізичного заліза через спеціальні драйвери VSP (Virtual Service Providers).
- Дочірні розділи (Child Partitions) — це ізольовані гостьові віртуальні машини, всередині яких запускаються операційні системи користувача; вони спілкуються з апаратним забезпеченням через клієнтські драйвери VSC (Virtual Service Clients).
- Шина VMBus — високошвидкісний внутрішній канал зв'язку, який з'єднує клієнтські драйвери гостьових ОС (VSC) з керівними драйверами батьківського розділу (VSP), минаючи складну емуляцію та суттєво підвищуючи швидкість вводу-виводу.
- Гіпервізор (Hypervisor layer) — тонкий шар програмного коду, який завантажується до старту будь-якої ОС, працює безпосередньо на «залізі» та розподіляє ресурси процесора і пам'яті між усіма розділами.
#### Ключові можливості Hyper-V
- Підтримка вкладеної віртуалізації (Nested Virtualization) — можливість запускати один гіпервізор Hyper-V всередині іншої віртуальної машини Hyper-V, що корисно для створення тестових лабораторій.
- Жива міграція (Live Migration) — перенесення увімкненої віртуальної машини з одного фізичного сервера на інший без зупинки її роботи та втрати зв'язку для користувачів.
- Реплікація Hyper-V (Hyper-V Replica) — вбудований механізм аварійного відновлення, який періодично копіює стан віртуальної машини на інший сервер через мережу для захисту від збоїв.
- Динамічна пам'ять (Dynamic Memory) — автоматичний перерозподіл оперативної пам'яті між активними віртуальними машинами в реальному часі залежно від їхнього поточного навантаження.
- Екрановані віртуальні машини (Shielded VMs) — технологія шифрування віртуальних машин за допомогою BitLocker, яка захищає дані всередині гостьової ОС навіть від адміністраторів самого фізичного сервера.
- Кроссплатформеність — повноцінна підтримка роботи не лише гостьових систем Windows, а й більшості популярних дистрибутивів Linux (Ubuntu, Red Hat, CentOS) та FreeBSD завдяки інтегрованим компонентам інтеграції (Integration Services).
#### Етапи для розгортання операційної системи на базі віртуальної машини VirtualBox.
###### 1.Завантаження образу ОС: Скачайте інсталяційний файл потрібної операційної системи у форматі .iso (наприклад, образ Ubuntu Linux або Windows) з офіційного сайту.
###### 2.Створення нової ВМ: Відкрийте VirtualBox і натисніть кнопку "New" (Створити) на верхній панелі.
###### 3.Первинне налаштування: У вікні, що з'явилося, вкажіть назву машини, виберіть папку для її збереження, а також вкажіть Тип (Type) та Версію (Version) ОС, яку збираєтеся встановлювати. Тут також можна відразу вказати шлях до завантаженого ISO-образу.
###### 4.Виділення оперативної пам'яті (RAM) та процесора (CPU): Вкажіть обсяг ОЗП та кількість ядер процесора, які будуть доступні віртуальній машині. Важливо залишатися в межах «зеленої зони» шкали, щоб не позбавити ресурсів основну (хостову) систему.
###### 5.Створення віртуального жорсткого диска: Виберіть опцію створення нового віртуального диска (зазвичай формат VDI) та вкажіть його максимальний розмір. Рекомендується обирати динамічний розмір (Dynamically allocated), щоб файл диска на реальному ПК розширювався поступово, а не займав усе місце одразу.
###### 6.Підключення інсталяційного образу (якщо не зроблено на кроці 3): Виберіть створену машину, натисніть "Settings" (Налаштування) розділ "Storage" (Носії). У списку пристроїв знайдіть віртуальний оптичний привід (іконка диска з написом "Empty"), натисніть на значок диска праворуч та виберіть пункт , щоб вказати шлях до вашого ISO-файлу.
###### 7.Запуск віртуальної машини: Натисніть кнопку "Start" (Запустити) на головній панелі VirtualBox.
###### 8.Встановлення гостьової ОС: Віртуальна машина завантажиться з ISO-образу, і на екрані з'явиться стандартне вікно інсталятора ОС. Пройдіть усі кроки встановлення (вибір мови, розкладки клавіатури, створення користувача та форматування віртуального диска), які ви б робили на звичайному комп'ютері.
###### 9.Перезавантаження та перший запуск: Після завершення інсталяції система попросить перезавантажитися. Переконайтеся, що VirtualBox автоматично «витягнув» ISO-образ із віртуального приводу (або витягніть його вручну через меню Devices -> Optical Drives), щоб знову не запустився інсталятор.
#### Чи є якісь апаратні обмеження при встановленні 32- та 64-бітних ОС?
###### Для встановлення 64-бітної операційної системи у віртуальній машині ваш фізичний процесор обов'язково повинен мати 64-бітну архітектуру та активовану в налаштуваннях BIOS/UEFI технологію апаратної віртуалізації Intel VT-x або AMD-V, без якої VirtualBox навіть не дозволить обрати такий тип системи. З іншого боку, 32-бітні операційні системи не мають таких жорстких вимог до технологій процесора і можуть запускатися на простішому залізі, проте вони мають критичне архітектурне обмеження, через яке фізично не здатні розпізнати та використовувати понад чотири гігабайти виділеної оперативної пам'яті.
#### Які основні етапи при встановленні OS Linux в текстовому режимі?
- Завантаження та ініціалізація інсталятора: Після запуску системи з носія (або ISO-образу у VirtualBox) у стартовому меню GRUB обирається варіант встановлення «Text mode», «Console install» або «CLI», після чого ядро Linux завантажується в оперативну пам'ять і запускає командну оболонку чи псевдографічний інтерфейс [BASIC INFORMATION ABOUT LINUX].
- Налаштування локалізації та клавіатури: За допомогою клавіш стрілок та Enter обирається мова інтерфейсу інсталятора, регіон (часовий пояс) та поточна розкладка клавіатури, що критично важливо для подальшого введення паролів та команд.
- Конфігурація мережі: Інсталятор намагається автоматично отримати IP-адресу через DHCP; якщо це не вдається або потрібне ручне налаштування, користувач самостійно вводить IP-адресу, маску підмережі, шлюз та адреси DNS-серверів, а також задає ім'я комп'ютера (hostname) і домен.
- Розмітка дискового простору (Partitioning): Це найвідповідальніший етап, на якому обирається диск і створюється таблиця розділів (GPT або MBR); користувач вручну або в напівавтоматичному режимі створює кореневий розділ (/), розділ підкачки (swap) та за потреби окремий домашній розділ (/home), обирає файлову систему (наприклад, Ext4 або XFS) та призначає точки монтування.
- Створення користувачів та безпека: На цьому кроці задається пароль для суперкористувача (root), а також створюється звичайний обліковий запис користувача, для якого вказується логін, повне ім'я та надійний пароль.
- Вибір та встановлення пакетів ПЗ: Користувач обирає базовий набір програмного забезпечення (наприклад, стандартні системні утиліти, SSH-сервер, вебсервер), після чого інсталятор форматує диски, розпаковує та встановлює базові пакети операційної системи й ядра Linux на жорсткий диск [BASIC INFORMATION ABOUT LINUX].
- Встановлення завантажувача: На системний диск (зазвичай у головний завантажувальний запис MBR або у спеціальний розділ EFI) записується завантажувач системи (найчастіше GRUB), який дозволить операційній системі коректно стартувати після перезапуску комп'ютера.
- Завершення інсталяції та перезавантаження: Інсталятор вивантажує тимчасові файли, пропонує вилучити інсталяційний носій (ISO-образ) і виконує перезавантаження комп'ютера, після якого система стартує вже безпосередньо з жорсткого диска у текстову консоль (TTY) для введення логіна та пароля [BASIC INFORMATION ABOUT LINUX].
#### Яким чином можна до установити графічні оболонки Gnome та KDE в Linux, якщо вона вже встановлена в текстовому режимі (вкажіть необхідні команди та пакети)? 
Для переведення операційної системи Linux із текстового режиму в графічний використовується штатний менеджер пакетів системи. Перед початком встановлення виконується обов'язкове оновлення списків доступного програмного забезпечення за допомогою команди sudo apt update.Для розгортання графічного середовища GNOME можна обрати один із трьох варіантів мета-пакетів. Перший варіант — це повна версія робочого столу Ubuntu, яка встановлюється командою sudo apt install ubuntu-desktop. Другий варіант — це мінімальна комплектація без стороннього програмного забезпечення, яка інсталюється командою sudo apt install ubuntu-desktop-minimal. Третій варіант — це оригінальний графічний інтерфейс без фірмових модифікацій, для якого використовується команда sudo apt install vanilla-gnome-desktop.Для розгортання графічного середовища KDE Plasma також доступні різні варіанти пакетів. Стандартний збалансований набір утиліт Plasma встановлюється командою sudo apt install kde-standard, а фірмова збірка з повним брендуванням та розширеним набором програм інсталюється за допомогою команди sudo apt install kubuntu-desktop.Під час завантаження файлів інсталятор у текстовому вікні попросить обрати дисплейний менеджер, який відповідає за екран входу в систему. Для середовища GNOME необхідно вибрати варіант gdm3, а для середовища KDE рекомендується обрати sddm. Після завершення процесу встановлення операційну систему перезавантажують командою sudo reboot, після чого вона автоматично стартує у звичному графічному режимі.
#### Коротка характеристика Gnome та JWM 
GNOME — це повнофункціональне, сучасне та одне з найпопулярніших графічних середовищ (Desktop Environment) у світі Linux, яке використовується як стандартне у таких великих дистрибутивах, як Ubuntu та Fedora [BASIC INFORMATION ABOUT LINUX]. Воно орієнтоване на простоту, чистоту інтерфейсу та максимальну зручність роботи, пропонуючи користувачеві повний набір фірмових додатків (текстовий редактор, файловий менеджер, відеоплеєр тощо) та єдину екосистему. GNOME має високі системні вимоги до процесора, оперативної пам'яті та обов'язково потребує підтримки 3D-прискорення відеокарти, через що його не рекомендується розгортати на слабких віртуальних машинах або застарілому залізі.
# 
JWM (Joe's Window Manager) — це надзвичайно легкий і мінімалістичний менеджер вікон (Window Manager) для графічної системи X11, написаний мовою C. На відміну від GNOME, він не є повноцінним середовищем і не містить вбудованих програм, а лише керує відображенням вікон, панеллю завдань та пусковим меню. JWM має феноменально низькі вимоги до апаратних ресурсів (може працювати навіть на комп'ютерах з кількома мегабайтами оперативної пам'яті), споживає мінімум дискового простору і дуже швидко завантажується, через що є ідеальним вибором для компактних дистрибутивів (як-от Puppy Linux), слабких серверів чи оптимізації швидкодії у віртуальних машинах.

#### 1.Порівняйте гіпервізори типу 1 та типу 2, яка між ними відмінність та сфера їх застосування?
##### Основні відмінності
Гіпервізори 1 типу (Bare-Metal) встановлюються безпосередньо на «голе залізо» (фізичний сервер) [1-29(a)]. Вони не потребують окремої операційної системи, оскільки самі виконують її роль, керуючи процесором, пам'яттю та дисками [1-29(a)]. Це забезпечує максимальну швидкість роботи віртуальних машин, високу безпеку та повну ізоляцію, адже збій в одній системі ніяк не зачепить інші.
# 
Гіпервізори 2 типу (Hosted) працюють як звичайні програми поверх вже встановленої операційної системи (хостової ОС), наприклад, Windows чи macOS [1-29(a)]. Вони змушені ділитися ресурсами з іншими програмами на комп'ютері та передавати всі команди через ядро хостової системи [1-29(a)]. Через таку багатошаровість їхня продуктивність нижча, а надійність залежить від стабільності основної ОС (якщо «впаде» Windows, вимкнуться й усі віртуальні машини) [1-29(a)].
##### Сфери застосування
Гіпервізори 1 типу використовуються в корпоративних середовищах, дата-центрах та хмарних сервісах (AWS, Azure, Google Cloud). Вони ідеально підходять для великих навантажень: консолідації компанійських серверів, хостингу великих вебсайтів та баз даних, де критично важливі стабільність 24/7 і максимальна швидкість [1-29(a)].

#### 2.Розкрийте поняття «GNU GPL», яка його основна концепція?
GNU GPL (GNU General Public License) — це одна з найпопулярніших та найвпливовіших ліцензій у світі програмного забезпечення, яка належить до категорії копілефт (copyleft) або ліцензій вільного ПЗ. Її створив засновник Фонду вільного програмного забезпечення Річард Столлман у 1989 році в рамках проєкту GNU (того самого, чиї інструменти у поєднанні з ядром Linux утворюють повноцінну операційну систему GNU/Linux) [BASIC INFORMATION ABOUT LINUX].
#### 3.В чому суть програмного забезпечення з відкритим кодом?
Суть програмного забезпечення з відкритим кодом (Open Source) полягає в тому, що творці програми роблять її вихідний код публічно доступним для всього світу. Це означає, що будь-яка людина, програміст чи компанія може вільно переглянути «внутрішню кухню» програми, зрозуміти, як вона працює, переконатися в її безпеці та змінити її під власні потреби.
#### 4.Що таке дистрибутив?
Дистрибутив — це повноцінна операційна система [BASIC INFORMATION ABOUT LINUX], готова до встановлення на комп'ютер, яка складається з базового ядра (наприклад, ядра Linux) [BASIC INFORMATION ABOUT LINUX], набору службових програм, системних бібліотек, графічного інтерфейсу та різноманітного прикладного програмного забезпечення (такого як браузери, офісні пакети чи текстові редактори).
#### 5.Які задачі системного адміністрування можна реалізувати на базі ОС Linux?
Операційна система Linux є світовим стандартом для серверної інфраструктури, що дозволяє системним адміністраторам реалізовувати повний спектр завдань з автоматизації, безпеки та підтримки ІТ-сервісів.У сфері керування мережевими службами адміністратори виконують розгортання базових інфраструктурних сервісів, таких як сервери автоматичного призначення адрес, служби доменних імен та точного часу. На базі Linux організовують хостинг веб-ресурсів за допомогою популярних вебсерверів та баз даних, а також налаштовують поштові та файлові сервери для обміну даними. Крім того, систему часто використовують як корпоративний маршрутизатор, шлюз або захищений фаєрвол для фільтрації мережевого трафіку та організації віддаленого доступу через віртуальні приватні мережі.Для адміністрування користувачів та контролю доступу Linux надає гнучкі інструменти управління обліковими записами, де адміністратор може створювати, видаляти або модифікувати профілі та групи. Тут реалізується точне розмежування прав доступу до файлів та папок через базові дозволи або розширені списки доступу, а також застосовуються системи примусового контролю безпеки. За потреби комп'ютери під керуванням Linux інтегрують у централізовані корпоративні каталоги для наскрізної автентифікації працівників.У напрямку керування ресурсами та сховищами здійснюється динамічний перерозподіл дискового простору за допомогою логічних томів, створення програмних масивів для надійності збереження даних та робота з сучасними файловими системами. Обов'язковою задачею є автоматизація створення резервних копій важливих конфігурацій з їх подальшою відправкою на віддалені сервери.Для моніторингу та обслуговування інфраструктури адміністратори організовують централізований збір і аналіз системних журналів для швидкого пошуку помилок. Рутинні завдання автоматизують за допомогою написання скриптів на мовах командної оболонки або Python, а також запускають регулярні процеси за розкладом через системний планувальник. Контроль продуктивності заліза здійснюється через постійне відстеження завантаження процесора, пам'яті, дисків та мережі.У сучасній практиці на базі Linux реалізують задачі віртуалізації та контейнеризації. Адміністратори керують ізольованими віртуальними машинами на рівні заліза за допомогою вбудованих гіпервізорів та розгортають легковажні контейнери для запуску додатків, об'єднуючи їх у великі керовані кластери.
#### 6.Як пов'язані між собою ОС Android та Linux? 
Операційна система Android побудована на базі ядра Linux, яке є її центральним та найголовнішим компонентом. Проте Android не є звичайним дистрибутивом Linux (як-от Ubuntu чи Debian), оскільки вся інша частина системи (програмне забезпечення, графічний інтерфейс та бібліотеки) розроблені компанією Google з нуля спеціально для мобільних пристроїв [BASIC INFORMATION ABOUT LINUX].
#### 7.Основні можливості та сфера використання Embedded Linux?
Embedded Linux (вбудований Linux) — це використання ядра та елементів операційної системи Linux у спеціалізованих мікропроцесорних системах, які інтегруються безпосередньо в різноманітні пристрої та прилади [BASIC INFORMATION ABOUT LINUX]. На відміну від універсальних дистрибутивів для настільних ПК чи серверів, вбудований Linux глибоко оптимізується та обрізається під конкретне апаратне забезпечення та завдання [BASIC INFORMATION ABOUT LINUX].
#### 8.Яким чином можна змінити типу завантаження Linux: в текстовому режимі (3 рівень) або графічному (рівень 5)? Чим відрізняються режими CLI та GUI?
У сучасних дистрибутивах Linux, які працюють під керуванням системи ініціалізації systemd, класичні рівні завантаження були замінені на спеціальні цілі (targets). Проте логіка їхнього використання залишилася незмінною, де текстовий режим (третій рівень) відповідає цілі multi-user.target, а графічний режим (п'ятий рівень) — цілі graphical.target.Щоб перевірити поточний режим завантаження, який встановлено в системі за замовчуванням, використовується команда systemctl get-default. Для постійної зміни типу завантаження на текстовий режим системний адміністратор вводить команду sudo systemctl set-default multi-user.target, а для постійного увімкнення графічного інтерфейсу застосовує команду sudo systemctl set-default graphical.target. Після введення будь-якої з цих команд операційну систему необхідно перезавантажити, щоб зміни набули чинності. Якщо ж потрібно змінити режим негайно без перезапуску комп'ютера, використовують команду ізоляції сесії, наприклад, sudo systemctl isolate multi-user.target для миттєвого вимкнення графіки або sudo systemctl isolate graphical.target для негайного запуску робочого столу з консолі.Режими взаємодії з операційною системою суттєво відрізняються своєю архітектурою та призначенням. Текстовий режим використовує інтерфейс командного рядка (CLI). У цьому режимі вся взаємодія користувача з комп'ютером відбувається виключно через введення текстових команд у терміналі, а відображення інформації обмежене текстовими символами. Головною перевагою текстового режиму є його мінімальне споживання ресурсів, оскільки система не витрачає оперативну пам'ять та потужність процесора на відмальовування візуальних ефектів. Це забезпечує максимальну швидкість роботи та високу стабільність, що робить текстовий режим ідеальним вибором для адміністрування серверів, роботи з базами даних та автоматизації скриптів.Графічний режим базується на використанні графічного інтерфейсу користувача (GUI). Він пропонує повноцінне візуальне середовище з вікнами, кнопками, панелями завдань, мишкою та робочим столом. Такий режим є набагато простішим та інтуїтивно зрозумілішим для звичайних людей, тому він є стандартом для домашніх та робочих персональних комп'ютерів, вебсерфінгу, офісних завдань та розробки програмного забезпечення. Проте графічний режим висуває значно вищі вимоги до апаратного забезпечення комп'ютера або віртуальної машини, оскільки потребує додаткових сотень мегабайт оперативної пам'яті, сильнішого завантаження процесора та обов'язкової підтримки відеокарти для рендерингу елементів інтерфейсу.
