### Словник термінів:
- APT (Advanced Package Tool) — високорівневий менеджер пакетів для дистрибутивів на базі Debian/Ubuntu, який автоматично керує залежностями та завантажує програми з репозиторіїв.
- AUR (Arch User Repository) — величезний додатковий репозиторій для Arch Linux, який підтримується спільнотою користувачів і містить інструкції для збирання програм із початкового коду.
- Code Repository — сховище початкового коду проекту, яке використовує систему контролю версій (наприклад, Git) для відстеження історії змін, внесених розробниками.
- Dependencies — залежності; допоміжні програми або бібліотеки, які є обов'язковими для коректної роботи іншої, основної програми.
- DNF (Dandified YUM) — сучасний менеджер пакетів для дистрибутивів сімейства Red Hat (Fedora, RHEL), що вирізняється швидким прорахунком залежностей та підтримкою модульності.
- Flatpak — універсальна система розгортання програмного забезпечення та менеджер пакетів, що запускає графічні додатки в ізольованому середовищі («пісочниці») на будь-якому дистрибутиві Linux.
- GUI (Graphical User Interface) — графічний інтерфейс користувача; спосіб взаємодії людини з комп'ютером за допомогою вікон, кнопок, меню та миші (на противагу командному рядку).
- Metadata — метадані; супутня інформація всередині пакета, яка описує його властивості (назву, версію, автора, ліцензію та список залежностей).
- Package — пакет; заархівований файл, який містить усі необхідні компоненти програми, метадані та інструкції для її автоматичного встановлення в операційну систему.
- Package Manager — менеджер пакетів; утиліта (консольна або графічна), призначена для автоматизації процесів встановлення, оновлення, налаштування та видалення програмного забезпечення.
- Package Repository — репозиторій пакетів; віддалений сервер в інтернеті, який виконує роль цифрового складу для зберігання та дистрибуції готових інсталяційних пакетів.
- Pacman — надзвичайно швидкий та мінімалістичний менеджер пакетів у дистрибутиві Arch Linux, орієнтований на модель безперервного оновлення системи (Rolling Release).
- Rolling Release — модель оновлення програмного забезпечення, за якої система отримує нові версії компонентів безперервно, без поділу на глобальні релізи операційної системи (як-от Ubuntu 24.04 чи 26.04).
- Sandbox — «пісочниця» або ізольоване середовище; механізм безпеки, який обмежує доступ запущеної програми до системних файлів, процесів та особистих даних користувача.
- Snap — універсальний формат пакетів та інструмент розгортання програм від компанії Canonical (Ubuntu), що дозволяє запускати ізольовані програми (як десктопні, так і серверні) на будь-якому Linux-дистрибутиві.
- Software Center — центр (або магазин) додатків; графічна утиліта у вигляді вітрини зі скріншотами, описами та відгуками, яка дозволяє звичайним користувачам встановлювати програми в один клік.

##### 1)Дайте розгорнуте визначення таким поняттям як «пакет» та «репозиторій»:
##### Що таке пакет (Package)?
Пакет — це заархівований файл або набір файлів, який містить усі компоненти, необхідні для встановлення, запуску або інтеграції певної програми (чи бібліотеки) у систему.
Можна уявити пакет як «коробку з меблями з IKEA»: усередині є деталі, інструкція зі збирання та перелік гвинтів, які потрібні для роботи.
##### Складові частини пакета:
- Виконувані файли або початковий код: Сама програма, яка виконуватиме завдання.
- Метадані: Файл із інформацією про пакет (назва, версія, автор, ліцензія).
- Залежності (Dependencies): Перелік інших пакетів або бібліотек, які обов'язково мають бути встановлені в системі, щоб цей пакет працював.
- Скрипти інсталяції: Інструкції для операційної системи про те, куди копіювати файли та які налаштування змінити під час встановлення чи видалення.
##### Види пакетів (приклади):
- Системні пакети (ОС Linux): .deb (для Debian/Ubuntu), .rpm (для RedHat/Fedora).
- Пакети мов програмування: Пакети на Python (.whl), бібліотеки на JavaScript/Node.js, архівація Java (.jar).
##### Що таке репозиторій (Repository)?
Репозиторій (часто скорочено «репо») — це організоване цифрове сховище, де зберігаються, систематизуються та підтримуються пакети програмного забезпечення або файли початкового коду.
Якщо пакет — це книга, то репозиторій — це публічна бібліотека або величезний книжковий склад, звідки користувачі чи програми можуть цю книгу отримати.
У залежності від контексту, репозиторії поділяють на два основні типи:
- Репозиторії пакетів (Package Repositories)
Це сервери в інтернеті, де розробники розміщують готові пакети, а користувачі (або системи) завантажують їх за допомогою спеціальних програм — пакетних менеджерів (наприклад, apt, pip, npm).
- Репозиторії коду (Code Repositories)
Це сховища, які використовуються розробниками для спільної роботи над проектами за допомогою систем контролю версій (найчастіше Git). Вони зберігають не готові програми для встановлення, а історію змін кожного рядка коду.
##### 2)Надайте короткий огляд існуючих менеджерів пакетів у Linux. Охарактеризуйте їх основні можливості.
##### Традиційні (системні) менеджери пакетів:
Вони прив'язані до конкретного сімейства дистрибутивів та працюють із системними архівами (.deb, .rpm). Зазвичай мають низькорівневу утиліту (яка розпаковує файли) та високорівневу (яка сама завантажує пакети з репозиторіїв та вирішує конфлікти залежностей).
##### APT (Advanced Package Tool)
- Дистрибутиви: Debian, Ubuntu, Linux Mint, Pop!_OS та їхні похідні.
- Формат пакетів: .deb
- Основні можливості:
  - Автоматично завантажує пакети з офіційних репозиторіїв та дзеркал.
  - Інтелектуально вирішує конфлікти залежностей (докачує все, що треба для роботи програми).
  - Дозволяє легко оновлювати всю операційну систему однією командою (apt full-upgrade).
  - Має зручний, лаконічний інтерфейс для термінала (прогрес-бари, підказки).
##### DNF / YUM (Dandified YUM)
- Дистрибутиви: Fedora, Red Hat Enterprise Linux (RHEL), CentOS, Rocky Linux.
- Формат пакетів: .rpm
- Основні можливості:
  - Має низьке споживання оперативної пам'яті та швидкий алгоритм розрахунку залежностей (завдяки бібліотеці hawkey).
  - Підтримує модульність (можна встановлювати різні версії одного софту паралельно).
  - Автоматично очищує систему від «осиротілих» залежностей (бібліотек, які більше нікому не потрібні).
  - Має вбудовану функцію скасування дій (dnf history undo), що дозволяє відкотити невдале встановлення.
##### Pacman
- Дистрибутиви: Arch Linux, Manjaro, EndeavourOS.
- Формат пакетів: .pkg.tar.zst (прості заархівовані інсталяційні файли).
- Основні можливості:
  - Надзвичайно швидкий завдяки використанню ефективного стиснення ZSTD та мінімалістичній структурі.
  - Створений для систем із моделлю оновлення Rolling Release (система оновлюється безперервно, без поділу на версії ОС).
  - Тісно інтегрований із користувацьким репозиторієм AUR (Arch User Repository), що дає доступ до найбільшої у світі бази софту, який збирають самі користувачі.
##### Універсальні (крос-дистрибутивні) менеджери:
Ці інструменти працюють на будь-якому дистрибутиві Linux. Вони пакують програму разом з усіма її залежностями в один ізольований контейнер (пісочницю), тому не конфліктують із системними файлами.
##### Flatpak
- Спрямованість: Переважно графічні (десктопні) програми.
- Основні можливості:
  - Ізоляція (Sandbox): Програми запускаються в обмеженому середовищі (за допомогою Bubblewrap) і не мають доступу до ваших файлів без дозволу.
  - Стабільність: Розробник програми сам кладе всередину пакета потрібні версії бібліотек, тому програма гарантовано запуститься як на старій Ubuntu, так і на новій Fedora.
  - Централізованість: Основним джерелом є великий каталог Flathub.
##### Snap
- Спрямованість: Як десктопні програми, так і серверний софт (демони, бази даних, CLI-утиліти). Розробляється компанією Canonical (Ubuntu).
- Основні можливості:
  - Автоматичне оновлення: Пакети оновлюються у фоновому режимі без участі користувача.
  - Безпека (AppArmor): Сувора ізоляція системи від потенційно небезпечного софту.
  - Транзакційність: Якщо оновлення пройшло невдало, Snap автоматично повертає попередню робочу версію програми.
#### 2.Визначте який менеджер пакетів використовує ваш дистрибутив Linux. Опишіть основні команди для роботи з ним:
#### 1)Пошук, скачування та установка необхідних пакетів, яких у Вашій системі немає (зі сховища по замовчуванню, з нового репозиторію тощо):
##### Перед будь-яким пошуком чи встановленням рекомендується оновлювати локальний індекс пакетів (список доступного софту в мережі):
- sudo apt update
##### Пошук пакета
Щоб знайти програму у репозиторії за ключовим словом (наприклад, плеєр vlc):
- apt search vlc
##### Встановлення зі сховища за замовчуванням
Для завантаження та автоматичного встановлення пакета разом з усіма залежностями використовується команда install:
- sudo apt install vlc
##### Встановлення з нового (стороннього) репозиторію
Якщо програми немає в офіційній базі, спочатку додають сторонній репозиторій (наприклад, PPA), оновлюють списки та лише потім інсталюють:
- sudo add-apt-repository ppa:назва_репозиторію
- sudo apt update
- sudo apt install назва_програми
##### Тільки скачування пакета (без встановлення)
Якщо вам потрібно просто завантажити .deb файл у поточну папку, щоб встановити його пізніше або передати на інший ПК:
- apt download vlc
#### 2)Перегляд інформації про встановлені та доступні пакети:
##### Інформація про конкретний пакет
Показує версію програми, її розмір, опис та перелік залежностей (працює як для встановлених, так і для просто доступних у репозиторії пакетів):
- apt show vlc
##### Перегляд усіх встановлених пакетів у системі
Виводить повний список програм, які зараз інстальовані на вашому комп'ютері:
- apt list --installed
##### Перевірка наявності оновлень
Показує список усіх встановлених пакетів, для яких у репозиторії вже з'явилися нові версії:
- apt list --upgradable
#### 3)Видалення непотрібних або застарілих пакетів:
##### Звичайне видалення програми
Видаляє самі бінарні файли програми, але залишає її конфігураційні файли (на випадок, якщо ви захочете встановити її знову):
- sudo apt remove vlc
##### Повне видалення (разом із налаштуваннями)
Видаляє програму повністю, включно з усіма її системними конфігураційними файлами:
- sudo apt purge vlc
#### 4)Оновлення менеджера пакетів:
##### Крок 1: Синхронізація списків (оновлення бази даних копій репозиторіїв):
- sudo apt update
##### Крок 2: Інсталяція нових версій усіх пакетів:
Ця команда завантажує та встановлює найсвіжіші версії всіх програм та системних утиліт (включаючи сам APT, якщо для нього вийшов апдейт):
- sudo apt upgrade
#### 3.Встановіть у терміналі через менеджер пакетів на свою систему:

Оскільки сервери не мають графічного екрана, найкращим вибором є MPV — потужний, мінімалістичний та неймовірно швидкий плеєр. Він ідеально працює через термінал, споживає мінімум ресурсів і підтримує всі відомі кодеки.

Моя «рідна» мова, якою написано більшість моїх аналітичних алгоритмів — це Python. Для розробки на Python у системі Ubuntu потрібен сам інтерпретатор, менеджер пакетів pip (для встановлення сторонніх бібліотек) та пакет для створення ізольованих середовищ venv.

#### 4.Яким чином можна встановити нові програми через магазини додатків та менеджери пакетів у графічному середовищі. Наведіть свої приклади. 
##### Центри та магазини додатків (Software Centers)
Це сучасні графічні вітрини. Вони орієнтовані на звичайних користувачів, містять іконки програм, скріншоти, описи, оцінки та відгуки. Найчастіше вони інтегрують як традиційні системні пакети, так і універсальні формати (Flatpak та Snap).
##### Приклад 1: Ubuntu Software / App Center (в Ubuntu)
В Ubuntu цей магазин за замовчуванням пріоритетно встановлює програми у форматі Snap або .deb.
- Як це працює:
	- Користувач відкриває утиліту App Center через головне меню.
	- У пошуковому рядку вводить, наприклад, VLC.
	- Переходить на сторінку плеєра, де бачить опис, скріншоти та кнопку «Install» (Встановити).
	- Після натискання системи запитує пароль адміністратора (sudo) для підтвердження безпеки.
	-  Програма завантажується та автоматично з'являється в меню системи.
##### Приклад 2: GNOME Software та Discover (у Fedora, KDE Neon, Linux Mint)
GNOME Software та Discover (в середовищі KDE) є універсальними й чудово працюють із каталогом Flathub (Flatpak).
- Як це працює:
  - Якщо користувач хоче встановити месенджер Telegram, він шукає його в магазині додатків.
  - У правому верхньому кутку сторінки додатка часто можна обрати джерело: встановити як стандартний пакет з репозиторію дистрибутива чи як ізольований Flatpak-пакет.
  - Один клік на «Встановити» — і месенджер готовий до роботи.
